# Руководство для отдела продаж

Как пользоваться CRM: ссылки агентов, разметка рекламы, расходы, лиды, отчёты, пользователи, прайс, копии базы. Адреса ниже примерные: `crm.example.com` - домен CRM, `example.com` - сайт проекта.

## Как пользоваться (для застройщика)

### 1. Завести агента и дать ему ссылку

1. **Агенты > Добавить агента.** Имя, телефон, Telegram. Slug ссылки создастся из имени (латиницей), можно задать свой: `nino`, `giorgi`.
2. Откроется окно "ссылки". У агента их две:
   - **Короткая** `https://crm.example.com/crm/a/nino` - для сообщений клиентам, сторис, визиток.
   - **Полная** `https://example.com/?a=nino` - если агент запускает свою рекламу, к ней добавляются utm-метки.
3. Там же - **ссылка для входа в кабинет** (без пароля, действует 7 дней на переход). Отправьте её агенту в Telegram. В кабинете агент видит только своё: клики, лиды, показы, брони, сделки и сравнение с медианой команды.
4. **Telegram-уведомления:** сначала **Настройки > Telegram**: создать бота у @BotFather (`/newbot`), вставить токен, "Подключить", получить код и отправить боту `/start <код>`. Агент привязывается так же кодом из своей карточки. Есть кнопка "Отправить тестовое сообщение". Для тех, кто не в Telegram, есть **e-mail уведомления** (SMTP в настройках, адреса через запятую, у агента e-mail в карточке).

Как это работает: посетитель, зашедший по ссылке агента, помечается на 90 дней. Все его заявки с сайта и просмотры квартир попадут этому агенту, даже если он оставит заявку через неделю без ссылки. Если посетитель раньше пришёл по ссылке другого агента, он останется за первым.

Ссылку входа можно перевыпустить в любой момент (старые перестают работать). Уволенного агента отключите переключателем "Активен": его ссылка перестанет назначать лидов, история сохранится.

### 2. Размечать рекламу

К любой ссылке на сайт добавляйте utm-метки, CRM сама определит канал:

| Где реклама | Ссылка |
|---|---|
| Meta (Instagram / Facebook) | `https://example.com/?utm_source=meta&utm_medium=cpc&utm_campaign=sep_sea&utm_content=video_1` |
| Google Ads | `https://example.com/?utm_source=google&utm_medium=cpc&utm_campaign=brand` |
| Telegram-канал / Telegram Ads | `https://example.com/?utm_source=telegram&utm_medium=post&utm_campaign=tg_batumi` |
| Яндекс | `https://example.com/?utm_source=yandex&utm_medium=cpc&utm_campaign=ya_search` |
| TikTok | `https://example.com/?utm_source=tiktok&utm_medium=cpc&utm_campaign=tt_sept` |
| Реклама от имени агента | к любой из ссылок выше добавить `&a=nino` |

Правила:
- `utm_source` - площадка (`meta`, `google`, `telegram`, `yandex`, `tiktok`). Синонимы `fb`, `instagram`, `ig`, `tg`, `ya` тоже понимаются.
- `utm_campaign` - название кампании, **оно же вводится в расходах**, тогда отчёт "по кампаниям" сведёт клики, лиды и деньги.
- `utm_content` - креатив (видео, карусель), чтобы видеть, что именно работает.
- Click id рекламных сетей (`fbclid`, `gclid`, `ttclid`, `yclid`) ловятся сами; если utm забыли, канал всё равно определится по click id или по referrer.
- Без меток и без referrer заход считается "прямым", с referrer из поиска - "органикой".

Правила "метка > канал" лежат в **Настройках** и редактируются без программиста. Там же кнопка "Определить канал" - вставьте ссылку и проверьте, куда она попадёт.

### 2а. Добавить свой канал рекламы

**Настройки > Каналы рекламы > Добавить канал.** Название ("YouTube"), код латиницей ("youtube", он же `utm_source` в ссылках), синонимы utm_source через запятую ("yt, youtube_ads"), переключатель "платный". Правило "utm_source = код" создаётся автоматически: ссылка `https://example.com/?utm_source=youtube&utm_campaign=...` сразу попадает в новый канал. Дополнительные условия (referrer, click id) добавляются в таблице правил ниже.

Там же канал можно переименовать, сделать бесплатным (расходы не вносятся, CPL не считается) или выключить (история остаётся, в отчётах канал показывается, в списках для выбора - нет). Системные "Агенты", "Органика", "Прямой" выключить нельзя.

### 3. Вносить расходы

**Расходы > Добавить расход:** канал, кампания (необязательно, совпадает с `utm_campaign`), период, сумма, валюта (USD / GEL / EUR, курс подставляется из настроек). Пачкой: "Импорт CSV" (шаблон внутри), подходит для выгрузок из рекламных кабинетов по дням.

Расход распределяется по дням периода: если внесли $900 за сентябрь, отчёт за неделю возьмёт 7/30 суммы. Дальше CRM считает сама:

| Метрика | Формула |
|---|---|
| CPL | расход / лиды |
| Стоимость показа | расход / показы |
| CAC | расход / сделки |
| ROAS | сумма сделок / расход |

Сумма сделки заполняется при брони (по умолчанию - цена квартиры из прайса, можно поправить). В ROAS попадают лиды в статусах "Договор" и "Оплачен" (меняется в настройках).

### 4. Работа с лидами

- **Откуда берутся:** форма на лендинге, кнопка "Заказать звонок" в подборе, ручной ввод (Лиды > Добавить лид), импорт CSV (шаблон внутри окна импорта).
- **Статусы:** новый > контакт > показ > бронь > договор > оплачен. "Потерян" - из любого статуса, причина обязательна (список причин редактируется в Настройках). Менять статус можно в карточке лида или перетаскиванием в Канбане.
- **Квартира:** для брони обязательна. При брони квартира на сайте помечается "бронь", при договоре/оплате - "продана", при потере брони - снова свободна. Если квартира уже забронирована другим лидом, CRM не даст поставить бронь и покажет, кем.
- **Повторные заявки:** если тот же телефон оставляет заявку повторно в течение 30 дней, новый лид не создаётся, в ленту существующего добавляется запись, ответственный получает уведомление.
- **Агент** может менять статусы до "Бронь" включительно. "Договор" и "Оплачен" подтверждает администратор.

### 5. Отчёты

- **Дашборд:** воронка клики > лиды > показы > брони > сделки, сравнение с предыдущим периодом.
- **Каналы:** та же воронка по каждому каналу и кампании + CPL, стоимость показа, CAC, ROAS. Переключатель "первое / последнее касание".
- **Агенты:** рейтинг за период, конверсия каждого шага против медианы команды.
- Показы, брони и сделки считаются по дате перехода в статус, а не по дате создания лида.

### 6. Пользователи, пароли, доступ

**Настройки > Пользователи.** Администратор может завести других пользователей: роль "администратор" (всё) или "только просмотр" (отчёты, лиды, карточки без правок, для владельца или маркетолога). Каждый меняет свой пароль сам ("Сменить мой пароль"), при смене остальные сессии завершаются. "Выйти на всех устройствах" на случай потерянного телефона. Отключённый пользователь войти не может, история его действий остаётся в журнале.

### 7. Прайс и статусы квартир

**Квартиры** > клик по квартире > цена и статус. Массово: "Экспорт CSV" > поправить цены в Excel > "Импорт прайса" (колонки `number`, `price`, `status`). Квартиры, занятые лидом (бронь, продажа), статус из файла не перезапишет. Каждое изменение цены пишется в историю.

### 8. Копии базы и восстановление

**Настройки > Копии базы.** Ночная копия делается сама в 03:00, хранится 30 штук. Кнопки: "Сделать копию сейчас", "скачать" (файл `.db` на свой компьютер), "Восстановить из файла" или из списка (сервис перезапустится, перед этим сохранится копия текущего состояния). "Полный экспорт JSON" выгружает все таблицы разом, если понадобится уйти к другому подрядчику.

### 9. Диагностика

**Настройки > Диагностика:** стоит ли сниппет на сайте, когда был последний клик и лид, подключён ли Telegram и e-mail, когда последняя копия, место на диске, уведомления, которые не ушли, последние 10 кликов. Если что-то красное, там же написано, что делать.

### 10. Свой сервер

CRM ставится на сервер и домен застройщика примерно за полчаса: `docs/INSTALL.md`. Скрипт `deploy/install.sh` ставит всё одной командой, база переносится через "скачать копию" > "восстановить из файла".

### 11. Демо-данные

Сейчас в системе демо: 5 вымышленных агентов, 60 лидов, 6 расходов, ~1 800 кликов, всё помечено `demo`. Перед началом работы **Настройки > Удалить все демо-данные**. Реальные записи не затрагиваются.

## Техническое

### Структура

```
server/           Fastify: index.js, db.js (схема + сид справочников), lib/ (attribution, leads, stats, auth, telegram, postbacks, email), routes/
public/           статика: admin/*.html, agent/*.html, js/crm.js + js/pages/*.js, css/tokens.css + crm.css, crm-track.js (сниппет)
db/schema.sql     схема SQLite
config/           channels.json (таксономия и правила utm -> канал), units.json (квартиры, единственный источник номеров)
seed/demo.js      демо-сид (5 агентов, 60 лидов, 45 дней)
deploy/           realestate-crm.service, nginx-crm.conf, install.sh (чистый Ubuntu одной командой), deploy.sh (обновление по SSH)
tools/            test.sh (npm test), e2e.sh (сквозной прогон), backup.sh (VACUUM INTO + gzip, 30 копий), build-artifacts.py
```

### Запуск локально

```bash
npm ci
cp .env.example .env          # для разработки можно не менять
npm run seed                  # демо-данные
npm start                     # http://127.0.0.1:3080/crm/admin/login.html, admin / admin
```

Пароль `admin` и dev-секрет сессии работают только вне production. С `NODE_ENV=production` сервер не стартует без `ADMIN_PASSWORD` и `SESSION_SECRET` (не короче 32 символов).

### Сервер

Первая установка: `deploy/install.sh` (см. `docs/INSTALL.md`). Обновление: `DEPLOY_HOST=user@server ./deploy/deploy.sh` (rsync, `npm ci`, перезапуск systemd, проверка `/api/health`).

Логи: `journalctl -u realestate-crm -f`. Копии базы: `$BACKUP_DIR/crm-*.db.gz`, ручное восстановление: `gunzip -c файл > $DB_PATH` при остановленном сервисе.

### Подключение к сайту

Одна строка перед `</body>` на каждой странице:

```html
<script src="https://crm.example.com/crm/crm-track.js" async></script>
```

Сниппет ловит utm/click id/referrer/`a=`, хранит посетителя 90 дней (cookie `crm_vid`, `crm_a`), шлёт просмотры квартир (`#/own/<id>`), даёт `window.crmTrack.lead({...})` для форм и `window.crmTrack.units(cb)` для статусов. На сайте формы вызывают `crmTrack.lead(...)` после успешной валидации, подбор накладывает статусы CRM на список квартир при старте.

### Telegram

Бот создаётся у @BotFather, токен вставляется в Настройки > Telegram (или `TG_BOT_TOKEN` в `.env`). Привязка чатов кодами через `/start <код>` (Настройки - админ, карточка агента - агент). Сервер опрашивает бота раз в 15 секунд.

### Постбэки конверсий (фаза 2)

Очередь `postback_queue` наполняется при смене статусов (Lead / Schedule / InitiateCheckout / Purchase) с хэшированным телефоном и click id первого касания. Отправка в Meta CAPI / Google offline / Telegram Ads не реализована: провайдеры выключены в настройках, записи помечаются `skipped`. Точка входа: `server/lib/postbacks.js -> processQueue()`.

### Сквозной прогон

```bash
npm test                                             # временная база, сид, e2e, проверка production-конфига
BASE_URL=http://127.0.0.1:3080/crm ADMIN_PASSWORD=admin tools/e2e.sh   # против запущенного сервера
```
Ссылка агента из meta > касание > просмотр квартиры > лид с сайта > контакт > показ > бронь > `units/status.json` отдаёт `reserved` > дашборды каналов и агентов за сегодня.
